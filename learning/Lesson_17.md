# Урок 17 — Несколько инструкций в одной транзакции (Batching)

---

## 1. Введение

В предыдущих уроках мы научились:

* формировать одну инструкцию (`transfer`);
* создавать `Message`;
* подписывать транзакцию;
* отправлять её и получать подтверждение.

Теперь мы делаем следующий шаг:
**в одной транзакции будет сразу несколько инструкций**, выполненных строго по порядку.

Это важно, потому что:

1. транзакции в Solana могут содержать **несколько действий**;
2. это уменьшает комиссии (см. Урок 16);
3. это делает логику атомарной — *выполняется всё или не выполняется ничего*;
4. это фундамент для сложных dApp — смарт-контракты ожидают набор инструкций.

---

## 2. Зачем объединять инструкции

### 2.1. Экономия комиссии

Если отправлять 5 инструкций отдельно:

```
5 транзакций × 10 000 лампортов ≈ 50 000
```

Если объединить:

```
1 транзакция ≈ 12 000 лампортов
```

Экономия огромная.

---

### 2.2. Атомарность (всё сразу или ничего)

Если в транзакции 5 инструкций:

```
execute(1) → execute(2) → … → execute(5)
```

Если какая-то из них не сможет быть выполнена, **вся транзакция откатывается**.
Это важно, когда данные должны оставаться согласованными.

---

### 2.3. Последовательность

Инструкции выполняются строго по порядку, как вы их добавили в список.

---

## 3. Что происходит внутри

Схема:

```
[Instruction 1]
[Instruction 2]
[Instruction 3]
       │
       ▼
   Message (со списком инструкций)
       │
       ▼
 Transaction (подпись)
       │
       ▼
     RPC send_transaction()
       │
       ▼
 Все инструкции выполняются последовательно
```

---

## 4. Минимальный пример: две инструкции transfer

Мы сделаем две инструкции перевода самому себе:

1. переведём 1 лампорт;
2. ещё раз переведём 1 лампорт;
3. упакуем всё в одну транзакцию;
4. посмотрим комиссию и результат.

Используем код из [`examples/Python/L17-Multi_instruction_transfer.py`](../examples/Python/L17-Multi_instruction_transfer.py):

```python
from solana.rpc.api import Client
from solders.keypair import Keypair
from solders.system_program import transfer, TransferParams
from solders.message import Message
from solders.transaction import Transaction

DEVNET = "https://api.devnet.solana.com"
client = Client(DEVNET)

# 1. Загружаем учебный кошелёк
with open("course_wallet.bin", "rb") as f:
    kp = Keypair.from_bytes(f.read())

pub = kp.pubkey()
print("Адрес:", pub)

# 2. Создаём две инструкции transfer
ix1 = transfer(TransferParams(
    from_pubkey=pub,
    to_pubkey=pub,
    lamports=1
))

ix2 = transfer(TransferParams(
    from_pubkey=pub,
    to_pubkey=pub,
    lamports=1
))

# 3. Получаем blockhash
latest = client.get_latest_blockhash().value
blockhash = latest.blockhash

# 4. Создаём Message из двух инструкций
msg = Message.new_with_blockhash(
    [ix1, ix2],   # список инструкций
    pub,
    blockhash
)

# (опционально) оценим комиссию
fee = client.get_fee_for_message(msg).value
print("Комиссия за две инструкции:", fee, "lamports")

# 5. Собираем и подписываем транзакцию
tx = Transaction([kp], msg, blockhash)
tx.partial_sign([kp], blockhash)

# 6. Отправляем транзакцию
sig = client.send_transaction(tx).value
print("Сигнатура:", sig)

# 7. Проверяем статус
st = client.get_signature_statuses([sig]).value[0]
print("Статус:", st)
```

## 5. Разбор примера

### 5.1. Список инструкций

Мы передали список:

```python
[ix1, ix2]
```

Это означает:

1. сначала выполняется перевод ix1;
2. потом сразу ix2;
3. если вторая не сможет исполниться — **обе отменяются**.

---

### 5.2. Подпись остаётся одна

Несколько инструкций **не требуют нескольких подписей**,
если все действия выполняются от имени одного аккаунта.

---

### 5.3. Комиссия меньше, чем две отдельные транзакции

Если отправить два перевода отдельно:

```
fee1 ≈ 5000
fee2 ≈ 5000
```

Вместе:

```
fee_total ≈ 5000–7000
```

---

## 6. Важное ограничение: порядок аккаунтов

Solana строит список всех аккаунтов, используемых в инструкциях:

* он объединяется;
* сортируется по правилам;
* разделяется на writable и readonly.

Если инструкции используют одни и те же аккаунты, порядок в списке должен быть правильный.
`solders` делает это автоматически, но важно знать:

* два transfer → один и тот же payer → всё корректно;
* несколько разных PDA и системных аккаунтов → список длиннее, комиссия выше.

## 7. Ошибки и их причины

| Ошибка               | Причина                                    | Решение                  |
| -------------------- | ------------------------------------------ | ------------------------ |
| `insufficient funds` | обе инструкции суммарно требуют больше SOL | уменьшить суммы          |
| `AccountNotFound`    | ошибка в получателе                        | проверить Pubkey         |
| `BlockhashNotFound`  | просрочен blockhash                        | получить новый           |
| `InstructionError`   | ошибка во второй инструкции отменяет обе   | проверить обе инструкции |

## 9. Ключевые выводы

* В Solana одна транзакция может содержать несколько инструкций.
* Это экономит комиссию и делает операцию атомарной.
* Инструкции выполняются строго по порядку.
* Commission можно оценить заранее через `get_fee_for_message`.
* Это фундамент для сложных транзакций dApp.
